## What it is

An app build's App view becomes a wall of **four fixed windows**, the same pattern as the game wall. Today it's a Preview/Code toggle (`web/index.html:131-151`, `web/canvas/rooms.js` `appEls`).

| # | Window | Shows | Live? |
|---|---|---|---|
| 1 | **Map** | The app as diagrams, drawn with **Mermaid** from the plan: screens and routes as a flowchart, data tables as an ER diagram. The step being built is highlighted, finished steps are ticked, and agents' notes are pinned on nodes (the visual feedback) | No. SVG drawn once per plan change |
| 2 | **Live app** | The app as the crew builds it, from the Dyad/Vite dev server with hot reload. Device switch (Phone/Tablet/Desktop) and Reload stay here | **Yes, only while building.** When building stops it turns into its latest photo |
| 3 | **Code** | The file being written right now, streaming, with its diff against the last version; the file tree on demand | No |
| 4 | **Shipped / next** | The last finished step: its name, a screenshot, and what changed in one line. Then the next step from the plan. After a deploy: the live address, version and time | No |

## How it behaves

- **Clickable, like the game wall:** a click (or Enter) on a window enlarges it to about three quarters of the wall, and the other three stack on its right. A second click or Esc puts it back. Keyboard: arrows move between windows.
- **Ask a window:** a chat question naming a crew member ("Pip, what are you on?") is answered by them, in the first person, in a bubble over their own window. An unnamed question is Hermia's, as on the game wall.
- **Cursors and skeletons:** each window shows its crew member's cursor while they work in it. A window with nothing yet shows a skeleton in its shape, with the working cursor and `aria-busy` (#418).
- **Phones (≤ 760 px):** the four windows become one at a time with a 4-dot switcher. Live app is the default while building, and Shipped/next after.

## The dev server only while building

- Dyad's dev server runs **only while the crew is building or you're editing**. It's what makes window 2 update instantly.
- When building stops, and after **2 min** with no viewer (owner, 2026-11-13; see the idle-shutdown work), Swarm runs `vite build` once and **serves the built files from its own server**. Window 2 and Play then show that static build, with no extra process.
- Reopening to edit starts the dev server again cold, with a skeleton and working cursor while it boots.
- Window 2 follows the image-first rule: when it isn't live, it's its photo.

## Data each window reads

- **Map:** the app plan (screens, routes, tables, steps) as Mermaid text generated by the server (`engine/appjob.mjs` / the plan), cached per plan version. Agents' notes come from the existing pins.
- **Live app:** today's `app-frame`, with `sandbox="allow-scripts allow-forms"` unchanged.
- **Code:** today's `app-tree` and `app-file`, plus the streamed edit events.
- **Shipped / next:** step events and snapshots (spec 36 storage), plus the deploy result (publish).
